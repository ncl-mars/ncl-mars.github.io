# CLAUDE.md

Personal portfolio: a SvelteKit static site with a raw WebGL2 renderer, hosted on GitHub Pages, plus the Houdini pipeline that produces its assets.

## Working rules

- Write code only inside this folder. Nothing outside it without the user's agreement: no temp files, no global memory, no installs. Scratch files go in `.tmp/` (gitignored), never `/tmp` or the system temp folder.
- Don't touch files the user is tuning live without asking.
- The user runs all git commands. Suggest commit messages, and never add a `Co-Authored-By` or any other attribution line.
- Answer planning questions in chat. Edit docs only when asked, or to keep the roadmap's decision log current.

## Memory

Notes live in `.claude/memory/`, **not** in the global `~/.claude/projects/.../memory/` folder. Save new notes there, one fact per file, and add a line to the index:

@.claude/memory/MEMORY.md

## Renderer (`web/src/lib/gl/`)

- One canvas, owned by `routes/+layout.svelte`. Pages get the renderer with `getRenderer()` and register DOM elements with `{@attach renderer.view(drawable)}`. Never create another canvas.
- Drawables (`lib/drawables/<name>/`) implement `init` / `update` / `draw` / `dispose` (`lib/gl/types.ts`). Constructors must not touch the DOM or GL (prerender runs in Node). Create GL resources in `init`.
- Programs come from `renderer.program(vs, fs)`, cached by source for the life of the context. Textures and other per-context resources go through `renderer.resource(key, create)`, cached the same way.
- State that must survive navigation (the home camera, the tour, the terrain drawable) lives in the `<script module>` of `routes/(site)/+layout.svelte`. That layout draws the scene for `/` and `/projects/<slug>/`, so it stays mounted between them.
- Content: no names in the code. `lib/assets/portfolio.yaml` (`doc/formats/portfolio.md`, read by `content/portfolio.ts`): your name, the home description. Where the POIs stand comes from `lib/assets/terrain/pois.json` (Houdini export, `doc/formats/pois.md`; id, x, z, menu order); everything else from the project folder `lib/assets/projects/<id>/` (`project.md`: YAML header with title, `view`, credits, media list; paragraphs under it; `doc/formats/projects.md`). `vite.config.ts` (`projectFiles`) parses `project.md` and `.yaml` files at build time (the `yaml` package never ships); `content/projects.ts` and `content/pois.ts` check the data and throw messages naming the file. Placeholders until the real exports.
- Navigation is by POIs (`lib/content/pois.ts`), one per project, all alike. Home is the overview, not a POI (`tour.current` is `HOME`, −1: no label is current there), framed by the start view (tuning group `start`); the POI views are relative to it (`zoom` × start distance, `turn` + start heading). `navigation/tour.ts` flies to any POI (labels, the masthead menu, folded behind a Projects button on phones; `camera.flyTo(pose)`, clearance planned up front), remembers home as you left it, and its controls only turn and zoom around the current pivot (drag, wheel, pinch, keys; not during a flight). The free controls (`gl/controls.ts`) are a dev tool, switched on from the panel ("Free camera", then "Copy pose" for a POI's `view` line in its `project.md`, or "Use view as start"). Dev panel buttons come from the `actions` map in `lib/tuning`.
- Projects (`lib/content/projects.ts`, one folder per POI with the same id; images through enhanced-img, videos as files; a project has a card only with some text or media): once the camera has arrived at a POI whose project has a card (`tour.onArrive`), its label shows a Data button, which navigates to `/projects/<slug>/` (prerendered with `entries()`); the `(site)` layout shows `components/ProjectOverlay.svelte`, a card over the live scene, from `page.data.project`. The URL is the truth: back closes the card, a project's URL brings the camera to its POI. Isolation is a CSS `backdrop-filter` over the scene and labels (tuning group `overlay`); the card scrolls on its own.
- The terrain draws in two passes: the march (`terrain.frag`) into a cache, only when `camera.revision` or a ground setting changes (sharp; on a device whose moving frames run slow, a rough, lower-resolution cache while the camera moves, then the sharp one once it has been still 0.15 s: `march.motionMode`, automatic by default); and the composite (`composite.frag`), every frame, with the atmosphere from `chunks/fog.glsl`. Light shafts: the march also stores in the cache's alpha the share of the air on each ray (mist and haze) that the sun reaches (`shafts.glsl`), through a shadow ceiling (`shadow.frag`, an RG8 map rendered once per ground, since the sun and the ground are fixed; coarse + fine channels, read as `r + g / 255` after filtering, in `shafts.glsl`'s `sunVisibility` and its mirrors in `composite.frag`, `sheet.frag`, `label.frag`); the composite passes it to `atmosphere(…, lit)`, and other passes get all-lit mist. A setting that feeds the cache (shafts and mist included) must call `terrain.invalidate()` (the `(site)` layout's tuning listener). The reference device is an old, cheap phone (90 Hz screen), target 60 fps. Anything drawn later in the scene includes `/noise`, `/wind`, `/fog` and uses `atmosphere()`, so it sits in the same mist. It takes those uniforms (and `/terrain`'s, to stand on the ground) from `terrain.sceneUniforms`, and is a second view on the scene element, attached after the terrain: views draw in attach order, after the composite wrote depth (example: `drawables/dust/`, stateless particles computed from `gl_VertexID`). A vertex shader that samples the heightmap declares `precision highp sampler2D` (vertex samplers default to lowp).
- Smooth noise in shaders: prefer the noise textures from `gl/noise.ts` (`renderer.resource('noise:3d' | 'noise:hash', …)`: tileable 3D gradient noise, 4 channels, sample with `p / 8`; hash for per-cell random values) over hashed value noise, which looks blocky at fine scale. `sampler3D` has no default precision in fragment shaders: declare it `highp`. The value noise in `/noise` stays for the terrain's far field, which the CPU mirrors. `/fog`'s mist banks read the 3D noise texture (`uNoise`), so a pass that includes `/fog` must have it bound (the terrain binds it and shares it through `sceneUniforms`).
- Dynamic resolution: when frames run long, the renderer first asks the visible drawables to get cheaper (`Drawable.degrade()`, one-way, remembered on the device: the terrain switches to its rough march in motion; the legend shadows' text in the air takes 8 samples instead of 16, never fewer), then scales the pixel ratio down, and back up when frames keep up (`tuning.renderer.adaptive` / `minScale`, "q" in the panel stats). Passes take sizes from `ctx.rect` and `ctx.pixelRatio`, never from `window.devicePixelRatio`.
- Shader chunks don't include each other: each shader includes what it needs, in order (`/common`, `/noise`, `/terrain`, `/wind`, `/fog`). Fragment shaders that use `/noise` declare `precision highp int`.
- The ground exists twice and must stay identical: `lib/gl/chunks/terrain.glsl` (GPU) and `lib/terrain/farfield.ts` + `ground.ts` (CPU: camera following, picking). Change both together. CPU code samples the ground through `Ground`, never the raw `Heightfield`. Heightmaps are 16-bit integer files (`r16-med`: packed losslessly by the exporter, MED-predicted and deflated, less than half the download, inflated by the browser's `DecompressionStream` and unpacked in `heightfield.ts`, mirroring `pack_med` in `export_heightmap.py`; `r16` raw; `r16f` half floats still read, rounded to integers at load), uploaded as they are into an RG8 texture, two bytes per sample (`Heightfield.texels`; R low, G high), which `terrain.glsl` puts back together (`heightTexel`: `(256 g + r) / 257`; `heightTexelExact` rounds fetched bytes to integers first). Hardware bilinear filtering isn't exact (8-bit sub-texel weights), which stepped steep slopes: `height()` is the GPU-filtered surface (one read: the march's big steps, dust, shadow ceiling), `heightExact()` / `terrainHeight()` / `terrainNormal()` filter in fp32 from four texels (the march near the ground, bisection, shading), when `uExactHeights` is set (tuning `march.exactHeights`). Sample heights only through these. The ground: the heightmap, blended into the optional far map (`farmap.bin`/`.json`, the same format, low resolution over a large area; an optional glob in `terrain/assets.ts`), blended into the endless noise; never below the sea (`uSeaLevel` / `Ground`'s `sea.level`, tuning `water.level`, 0 by contract: the exports' altitude 0): `height()` / `heightAt()` is the surface, `terrainHeight()` / `terrainAt()` keeps the seabed (the water's depth). The shadow ceiling (always rendered) also shades the terrain past the baked maps. The water: the march snaps water hits exactly onto the sea plane and colours them from the depth (shallow to deep, foam at the shore, `shade.glsl`); the composite recognises them by their height and adds the moving part (wave normals from the noise texture, mip-filtered by distance; Fresnel reflection of the sky; the sun's glint, cut by the shadow ceiling): the terrain stays cached (tuning group `water`). The ground's surface (`shade.glsl`, cached): the sun's light is n·L from the heightmap's normal (`terrainNormal`: a texel apart, a far-map texel over the far map, so its bilinear cells don't show; a pixel's footprint apart far away) × the shadow baked in `maps.png` R (the shadow ceiling past the heightmap), × its AO and cavity. Materials from the optional `materials.png` (R metal, G gloss, B spare soft masks, the ground the rest; an optional glob like the far map; where the masks are steep the largest weight wins, anti-aliased with `fwidth`, where they ramp gently they blend by their values (`materials.blend`: the ramp's width in texels, from the masks' derivatives through uv's), the objects against the ground first, then within the objects; faded past the heightmap). The colour is the same whatever the material: the optional `albedo.png` inside the heightmap (the objects' colours painted in too) and `faralbedo.png` over the far map (display values, lossy WebP; each faded out over its map's band, `farMask()` for the far one), else the tint (rock is painted into the albedo: no rock rule), with a variation from the noise texture (tuning group `ground`, "Ground colours"). A material changes only how it's lit: the ground is matte; metal, gloss and spare (generic slots: a tint of the colour, how metallic, how rough) reflect the sky (`environment()`, a mirror of `/fog`'s `skyColor`: change both together) and the sun's highlight (tuning group `materials`).
- Views are expected in normal document flow: rects are cached in document space, so a `position: fixed` view on a scrolling page would drift.
- Shader hot reload: each drawable module ends with `import.meta.hot.accept([...shader paths], …)` calling `hotSwap()`. Copy the block from `drawables/test/TestPattern.ts`, using relative paths.
- Never read layout in the frame loop. Rects are cached in document space; visibility is arithmetic.
- DOM overlays that follow the scene (the legend labels) update from `renderer.onFrame(cb)`, which runs after each rendered frame. Write `el.style` / attributes directly, only when the value changed, never through Svelte state.
- Legend lines (`components/Legend.svelte` + `legend/legend.ts`): HTML labels tied to ground points by SVG hairlines. Put the component inside the view element (it fills it). Label sizes come from a ResizeObserver. Labels fade with the mist through `terrain/atmosphere.ts`, a CPU mirror of `fog.glsl` (distance fog + mist, no banks): change both together. They never fade below `mistFloor`. The ridge test looks from `occlusionLift` above the point, so a point a little behind a crest keeps its label. Legend shadows: after each frame the legend writes its lines in 3D (`legend/lines.ts`: each segment unprojected at its anchor's depth, so on a plane facing the camera, exactly under the drawn line); `drawables/legend-shadows/` draws each segment's shadow in the god rays as an instanced box reaching away from the sun, between the terrain and the dust, darkening colour by colour (`dst × (1 − src)`: in the air the sun's share of the haze, so shadowed air turns cooler; neutral on the ground) by jittered samples along each ray's exact stretch inside it, the line's shadow blurred by the sun's disc with distance (`softness`, a trapezoid profile), and the ground where a ray meets it inside the box. The labels' text shades the ground and the air (jittered samples along each ray's stretch in the box, the mask blurred to the gap between them) too: the legend also writes each shown label's text box in 3D and its text; the drawable draws the text into a mask atlas with a 2D canvas (same fonts, letter by letter for the CSS letter-spacing; `drawMask` mirrors Legend.svelte's label CSS, and `BOX_*` in legend.ts) and `label.frag` reads it where the sun ray from the ground crossed the box (tuning group `legendShadows`). It reads the shadow ceiling through `terrain.sceneUniforms`; `sheet.frag` mirrors `shafts.glsl`'s `sunVisibility`. In the callout layout, labels are placed nearest first (the current POI's first) and rise out of each other's way; the label box sizes in em (`BOX_*` in `legend.ts`) mirror the CSS in `Legend.svelte`.
- `/lab/views/` is the view-system test page.
- HTML that must sit on a 3D quad in perspective: `gl/homography.ts` gives the CSS `matrix3d`, updated in `renderer.onFrame()`.
- Meshes with vertex attributes use explicit `layout(location = 0)` so VAOs survive shader hot reload.
- Pages whose content scrolls over a fixed GL view scroll an inner fixed container, never the window, so the view's cached rect stays valid.

## Tuning (`web/src/lib/tuning/`)

- Every tunable value (camera, controls, march, shading, fog, renderer) lives in `defaults.json`. Code reads `tuning.<group>.<key>` live, every frame or event; don't copy the values into locals at construction.
- Adding a value: add it to `defaults.json`, describe it in `schema.ts` (label, range, hint), read it from `tuning`. If changing it needs an action, use `onTuningChange` (e.g. the pixel-ratio cap in the root layout).
- Dev panel (`lib/components/DevPanel.svelte`, dev only, P toggles): stats, live readouts (`readouts` map, registered by pages), and sliders. "Save defaults" writes `defaults.json` through the dev server endpoint `/__tuning/save` (`vite.config.ts`), which checks the shape first. `tuning/index.ts` hot-accepts `defaults.json`, so saving doesn't reload the app.

## Commands

Run from `web/` (in Bash: `cd web && …`). The default Node is 22.12.0 and **must not be changed** (Mont-Blanc pins it). That's why this is SvelteKit 2, not 3 (see `doc/stack.md`).

- `npm run dev`: dev server with hot reload
- `npm run build`: static site to `web/build/`
- `npm run check`: type check (`svelte-check`). This is the only static check: no linter, no tests.
- `npm run gen:terrain`: placeholder heightmap + maps into `src/lib/assets/terrain/` (refuses to overwrite without `-- --force`, the files may be a real Houdini export)

Smoke-testing the dev server on Windows: stopping the background `npx vite dev` leaves its `node` child listening. Kill the process that owns the port afterwards (PowerShell `Get-NetTCPConnection -LocalPort <port>` → `Stop-Process`).
