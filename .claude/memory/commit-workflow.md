The user runs every git command and likes it: it lets them batch follow-up fixes into one clean commit and review `git status` first. When a piece of work is done, give the commit as one block (`cd D:/Web/portfolio`, `git add -A`, `git commit -F .tmp/commit-msg.txt`). Everything that isn't gitignored gets committed, the terrain exports and `hou/*.hiplc` included: the user tracks them ("I need to keep track of the gen_maps, the maps and all", 2026-11-03). Only the DEM data and saved terrain sets stay out, in `hou/geo/` (gitignored, [[terrain-sets]]). That day Claude misread "I don't want to pack heavy assets" as keeping the exports out of commits and handed over a commit without them: wrong, and the user was angry. If more changes land before they commit, re-send the full updated block rather than a diff of the message. Suggest branch names when asked (`feature/<milestone>-<topic>`, they also used `dev-panel`).

**Why:** The user confirmed the workflow ("me doing the commit allows better commits") after a dev-panel commit that absorbed three follow-up tweaks.

**How to apply:** No commits, no `Co-Authored-By` (see CLAUDE.md). Messages: a short summary line, a blank line, then bullets grouped by what changed. Plain ASCII only: no apostrophes (write "of the POI", not "POI's"), no curly quotes or dashes. On 2026-10-29 a message with apostrophes broke the commit twice while the user thought it had landed. On 2026-11-03 a pasted here-string got the terminal's paste marker `[200~` at the start of the summary line: since then the message goes into `.tmp/commit-msg.txt` (written by Claude) and the block runs `git commit -F .tmp/commit-msg.txt`, so nothing multi-line is pasted. Forward slashes in every path of the block: the user's terminal ate the backslash of `.tmp\commit-msg.txt` and the commit failed. Never run `git commit` yourself, not even `--dry-run` (the user rejected one); read-only `git status` / `git log` are fine. After a commit, a read-only `git log --oneline -1` confirms it. Before suggesting any merge, checkout or branch command, run a read-only `git branch --show-current` / `git log --oneline -3` / `git branch --merged develop` and only suggest what is still needed: on 2026-10-29 the user had merged a branch and was annoyed to be handed the merge again ("can you keep up?").
